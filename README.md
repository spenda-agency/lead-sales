# lead-sales: リード獲得後の営業自動化(第一弾)

3つのリード獲得経路について、「新規リード検知 → AIが1件ずつ下書きを作成 →
人が内容を確認・承認 → 送信」という一連の流れを、Google Apps Script (GAS) 上に
自動化したもの。社内マニュアル「営業AI活用フロー」の考え方
（AIは下書きまで、最終判断と送信は人）をそのままコード化している。

## 対象にしているリード源

| | 経路 | 想定される主な相手 | データの置き場所 |
|---|---|---|---|
| ① | ホームページからの問い合わせ | 法人が多い | スプレッドシート(既存タブ) / HubSpot |
| ② | LINE公式アカウント登録者 | 個人が多い | LINE Webhook経由でスプレッドシートに集約(新規) |
| ③ | 他社WEBサイトのフォーム経由 | - | スプレッドシート(既存タブ) |

パイプラインは毎回 **①→②→③の順** に新規分だけを処理し、それぞれ
Claude APIで1件ずつパーソナライズした下書きを作って「リード確認」シートに
書き出す。**この時点では一切送信しない。**

人がシート上で下書きを確認し、問題なければ「承認」列にチェックを入れる。
その後 `sendApprovedLeads`（メニューまたは定期トリガー）が、承認済み・未送信
の行だけをメール(①③)またはLINE(②)で送信する。

## ハウスリストの行動スコアリング(社内マニュアル工程①)

新規リードとは別に、既存のハウスリスト(HubSpotコンタクト)の行動を
スコアリングし、閾値を超えた「今このタイミング」の相手だけをAI下書きの
対象にする仕組みも含んでいる。

- 行動データはHubSpot CRM API(Contacts)から取得する。サイト訪問数は
  標準プロパティ`hs_analytics_num_page_views`(トラッキングコード必須)、
  メール開封は既定で`hs_sales_email_last_opened`(直近のセールスメール
  開封日時)を使う。**`hs_email_open`はマーケティングメールの開封数
  プロパティでMarketing Hub専用のため、Sales Hubのみの契約では使えない**
  (Marketing Hubも契約している場合は`HUBSPOT_EMAIL_OPEN_PROPERTY_TYPE`を
  `count`にして`hs_email_open`を指定すれば累積カウント方式に切り替え可能)
- 開封シグナルが「日時」方式の場合、1回のスコアリング実行で複数回開封が
  あっても1件としてしか加点されない(件数を区別できないSales Hub Starter
  の制約による割り切り)
- 「スコア設定」シートに配点(サイト訪問1回=2点、メール開封1回=1点)と
  通知閾値(5点)を用意している。運用しながら**このシートの数値を直接
  書き換えるだけで**調整できる(コード変更不要)
- 「ハウスリストスコア」シートで、コンタクトごとに前回通知時点からの
  増分を追跡する。閾値を超えたら、その時点の値を新しい基準値としてリセット
  するため、同じ理由で何度も通知が来ることはない
- 閾値超過時は、他の3経路と同じ「リード確認」シートに
  `④ハウスリスト掘り起こし` として追加され、以降の確認・承認・送信の
  流れは共通

## セットアップ

### 1. スプレッドシートを用意する

このスクリプトをコンテナバインドするGoogleスプレッドシートに、以下のタブを用意する。

- `①HP問い合わせ`：既存の問い合わせスプレッドシート、または同じ内容をコピーしたタブ
- `②LINE登録者`：空でよい（LINE Webhookが自動的に行を追加する）
- `③他社フォーム経由`：既存の他社フォーム集約用スプレッドシート
- `リード確認`：空でよい（`runPipeline`実行時に自動作成される）

タブ名を変える場合は、Script Propertiesの `SOURCE1_SHEET_NAME` 等で上書きできる。

既存シートの列名（見出し）が `src/Source1_WebForm.gs` や
`src/Source3_OtherForms.gs` にある `HEADER_CANDIDATES` と一致しない場合は、
実際の見出し文字列を配列に追加すること。

### 2. clasp でこのリポジトリを紐付ける

```bash
npm install -g @google/clasp
clasp login
cp .clasp.json.example .clasp.json   # scriptId を実際のGASプロジェクトIDに置き換える
clasp push
```

### 3. Script Properties を設定する

Apps Script エディタ > プロジェクトの設定 > スクリプト プロパティ で設定する。

| キー | 必須 | 説明 |
|---|---|---|
| `DRY_RUN` | - | `false` にするまでは何も実送信しない安全モード（デフォルトtrue） |
| `ANTHROPIC_API_KEY` | 推奨 | Claude APIキー。未設定でもテンプレート下書きで動作する |
| `ANTHROPIC_MODEL` | - | デフォルト `claude-sonnet-5` |
| `LINE_CHANNEL_ACCESS_TOKEN` | ②を使うなら必須 | LINE Messaging APIのチャネルアクセストークン |
| `SLACK_WEBHOOK_URL` | 任意 | 新規下書き発生時の通知先 |
| `SENDER_NAME` / `SENDER_EMAIL` / `COMPANY_NAME` | 推奨 | 下書き文面に使われる |
| `EMAIL_SEND_MODE` | - | `draft`(Gmail下書きに保存、デフォルト) または `send`(即送信) |
| `SOURCE1_SHEET_NAME` 等 | - | タブ名を変えている場合に上書き |
| `HUBSPOT_API_TOKEN` | 行動スコアリングを使うなら必須 | HubSpot Private Appのアクセストークン(スコープ: `crm.objects.contacts.read`, リスト機能を使うなら`crm.lists.read`も) |
| `HUBSPOT_HOUSE_LIST_ID` | 任意 | 特定の静的リストだけを対象にしたい場合のリストID。未設定なら全コンタクトが対象 |
| `HUBSPOT_MAX_CONTACTS` | - | 1回の実行でスコアリングする上限件数(デフォルト500) |
| `HUBSPOT_PAGEVIEWS_PROPERTY` / `HUBSPOT_EMAIL_OPEN_PROPERTY` | - | 実際のプロパティ名に合わせて変更可能 |
| `HUBSPOT_EMAIL_OPEN_PROPERTY_TYPE` | - | `date`(既定値、直近開封日時) または `count`(累積開封数。Marketing Hub契約時のみ) |

設定後、Apps Scriptエディタで `checkConfig` を実行するとログで設定状況を確認できる。

### 3.5 HubSpot側の準備（行動スコアリングを使う場合）

1. **Private Appを作成してトークンを発行する**：HubSpot管理画面の
   設定(歯車アイコン) > 連携アプリ > プライベートアプリ で新規作成し、
   スコープに `crm.objects.contacts.read` を付与する（静的リストで絞り込む
   場合は `crm.lists.read` も）。発行されたトークンを`HUBSPOT_API_TOKEN`に設定
   - Private App機能自体はStarterプラン以上（無料プランでも一部)で利用可能
   - **Hub ID（例: 45097073）はアカウント自体を識別するIDで、プロパティ名とは別物。
     コード側では使わない**
2. **実際に使えるプロパティ名を確認する**：設定 > プロパティ > 対象のオブジェクトで
   「コンタクトのプロパティ」を選び、「ページビュー」「メール」等で検索して、
   自社ポータルで実際に使われている内部名を確認する。テスト用に1件コンタクトの
   詳細画面を開き、アクティビティに「ページ閲覧」や「メール開封」のログが
   実際に記録されているかも合わせて見ておくと確実
   - サイト訪問：自社サイトにHubSpotトラッキングコードが入っていないと
     `hs_analytics_num_page_views`は増えない
   - メール開封：Marketing Hub未契約（Sales Hub Starterのみ）の場合は
     `hs_email_open`が使えないため、既定値の`hs_sales_email_last_opened`
     (日時)のままにしておく
3. 上記1・2の内容がコードの既定値と違う場合は、Script Propertiesで
   `HUBSPOT_PAGEVIEWS_PROPERTY` / `HUBSPOT_EMAIL_OPEN_PROPERTY` /
   `HUBSPOT_EMAIL_OPEN_PROPERTY_TYPE` を上書きする

### 4. LINE Webhookを設定する（②を使う場合）

1. Apps Scriptエディタで「デプロイ」→「新しいデプロイ」→種類「ウェブアプリ」
   - 実行するユーザー: 自分
   - アクセスできるユーザー: 全員
2. 発行されたURLに `?source=line` を付けて LINE Developers コンソールの
   Messaging API設定 > Webhook URL に設定し、Webhookを有効化する
3. 友だち追加(follow)イベントが届くと、自動的に `②LINE登録者` シートへ
   表示名とユーザーIDが追記される

**制約**: Apps ScriptのdoPostはHTTPリクエストヘッダーを受け取れないため、
LINEの署名検証(x-line-signature)はこの実装では行っていない。
より厳密にしたい場合は、ヘッダーを扱える別の実行環境（Cloud Functions等）を
Webhook受け口にし、そこからこのスプレッドシートへ書き込む構成に変更すること。

### 5. WordPressフォームの自動転記を設定する

自社サイト(/media/配下のWordPress)の問い合わせ・資料DLフォームを、
指定のスプレッドシートに自動転記できる。同じウェブアプリURLに
`?source=wpform&token=...` を付けてWordPress側から送信する。
詳細な手順は [docs/wordpress-webhook-setup.md](docs/wordpress-webhook-setup.md) を参照。

## 日常の使い方

スプレッドシートを開くと「営業自動化」メニューが追加される。

1. **① 新規リード取得＋下書き作成**：①→②→③の順に新規分だけ処理し、
   「リード確認」シートに下書きが追加される（Slack通知が来る場合はそちらも見る）
2. **② ハウスリスト行動スコアリング実行**：閾値を超えたコンタクトがいれば
   同じく「リード確認」シートに追加される
3. 「リード確認」シートで `AI下書き` 列を読み、事実誤認や違和感がないか確認する
4. 問題なければ `承認` 列にチェックを入れる
5. **③ 承認済みリードを送信**：承認済み・未送信の行だけを実際に送信する

「定期実行トリガーを設定」を実行すると、①③の処理を30分おきに、
②の行動スコアリングを1時間おきに自動実行する
（それでも送信は承認された行だけ、というルールは変わらない）。
